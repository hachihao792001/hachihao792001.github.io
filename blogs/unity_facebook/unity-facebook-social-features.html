Kinh nghiệm từ việc implement tính năng Social với Facebook trong Unity

Vừa qua mình được giao task cài đặt các tính năng Social trên Facebook cho game ở job của mình. Vì phải build đi build lại khá nhiều lần và kẹt ở những khâu mà mình nghĩ sẽ không kẹt, nên mình quyết định viết blog này để bạn có thể tránh được những thứ mà mình đã tốn nhiều thời gian thử sai

Disclaimer: Blog này không phải tutorial từ đầu tới cuối, giờ có AI thì việc tìm và đọc doc về những thứ cơ bản sẽ khá là nhanh. Blog này chỉ nêu lên những kinh nghiệm, hướng đi của mình trong quá trình làm (mà AI không giúp được), để tiết kiệm thời gian của bạn trong lúc làm.

Các tính năng social cụ thể là:

  • Lấy list friend Facebook và in-game info của từng friend
  • Mời bạn bè chơi game qua tin nhắn Messenger
  • Share thành tựu lên tường nhà kèm screenshot

1. Setup trên Meta Developers

a. App type / Use case và quyền

Đối với trường hợp của mình, thì Game thật ra đã có sẵn app trên Meta Developers, tuy nhiên app đó được config để ưu tiên AdMon, Marketing. Cụ thể nó có App type là Business.

App type Business sẽ không làm được các tính năng liên quan tới bạn bè. Chỉ app có app type là Gaming và Consumer thì mới làm được. Và một sự thật phũ phàng nữa là Meta sẽ không cho mình thay đổi setup đó.

Cho nên nếu bạn cũng gặp trường hợp tương tự như mình, thì bạn không còn cách nào khác ngoài tạo app mới

Một cái bạn nên để ý là bây giờ Meta Developers không còn khái niệm App type nữa, mà chỉ có Use cases, và Use case thích hợp để làm các tính năng Social là cái này:

Tuy nhiên có một trade-off: khi đã chọn use case Authenticate trên, hầu hết mọi use case còn lại đều bị làm mờ, ngoại trừ use case liên quan tới Meta Ads Manager.

Vì vậy app này sẽ không thể dùng để làm các tính năng liên quan tới Marketing mà AdMon và UA thường cần (A small price to pay for salvation).

Giải pháp mà mình đã bàn với team là giữ App marketing cũ chạy tiếp nhưng không kết nối với client game, chỉ kết nối client với App mới này để làm được các tính năng login, bạn bè, ...

Sau khi đã tạo app, ta customize use-case Authenticate để có các quyền public_profile, email, user_friends:

  • public_profile cho mình lấy thông tin cơ bản của user như tên và avatar
  • email cho mình lấy email của user dùng trong Facebook
  • user_friends cho mình lấy danh sách bạn bè Facebook của user mà cũng chơi game này. Với các use case liên quan tới Marketing thì sẽ không hề có quyền này.

Để tính năng Login Facebook, bạn bè, ... có thể sử dụng được với mọi user, thì trước tiên các quyền mình dùng cần có Advanced access. Muốn có Advanced access thì App phải được thông qua App Review của Meta.

Mình khuyên nên tạo Test users vì thứ nhất là mình không cần dùng tài khoản Facebook cá nhân của mình, và thứ hai là những test user này cho phép mình lấy Access Token dễ dàng. Điều này rất hữu dụng vì cho phép mình test ngay trong Editor mà không cần build ra device (sẽ nói sau).

Tuy nhiên khi tạo Test users này thì Meta thường lỗi, không hiện email (như hình trên) hoặc mật khẩu. May là Meta cho phép "Login as this test user" ngay mà không cần credentials đó:

Về phần submit App Review, mình có các lưu ý:

  • Về quyền user_friends, Meta sẽ hỏi mình sử dụng nó như thế nào và mình phải cung cấp video demo việc sử dụng nó trong game.

  • Cuối cùng phần Review Instructions sẽ yêu cầu upload APK kèm hướng dẫn cách access phần Connect Facebook và một video demo.

b. Lấy info cơ bản và list friend

Mình dùng Graph API để lấy thông tin đó bằng hàm FB.API. Mình để ở đây một vài code snippet để bạn dễ copy-paste (mình tối giản code lại để dễ nhìn, thực tế là phải check null, try catch các thứ).

Class chứa thông tin user và hàm parse: 
public class FBUserInfo
{
    public string fbId;
    public string fbName;
    public string fbAvatarUrl;
}

FBUserInfo ParseUserNode(JSONNode node)
{
    string id = node["id"].Value;
    string name = node["name"].Value;
    string avatarUrl = node["picture"]["data"]["url"].Value;
    return new FBUserInfo(id, name, avatarUrl);
}
Lấy info cơ bản: 
FB.API("/me?fields=id,name,picture.width(128).height(128)", HttpMethod.GET, (result) =>
{
    FBUserInfo me = ParseUserNode(JSONNode.Parse(result.RawResult));
});
Lấy friends: 
FB.API("/me/friends?fields=id,name,picture.width(128).height(128)&limit=100&summary=true", HttpMethod.GET, (result) =>
{
    List<FBUserInfo> friends = new List<FBUserInfo>();
    JSONNode root = JSONNode.Parse(result.RawResult);
    JSONNode data = root["data"];
    if (data != null)
    {
        for (int i = 0; i < data.Count; i++)
            friends.Add(ParseUserNode(data[i]));
    }

	// data.Count là số bạn bè cũng có chơi game (có thể access info), totalCount là tổng số bạn bè trên Facebook của user (không thể access info)
    int totalCount = root["summary"]["total_count"].AsInt;
});

4. Liên kết Facebook SDK với các tính năng in-game bằng PlayFab

Có danh sách bạn bè Facebook rồi, nhưng ta cần cách lấy được in-game data của những bạn đó. Mỗi user Facebook có Facebook ID để định danh, nhưng thay vì lưu in-game data tương ứng với từng Facebook ID ở database nào đó, ta có thể dùng PlayFab.

PlayFab có hỗ trợ liên kết với Facebook bằng API Link Facebook Account, cùng với hàm PlayFabClientAPI.LinkFacebookAccount để gọi trong SDK của PlayFab, chỉ cần truyền vào token của facebook (Facebook.Unity.AccessToken.CurrentAccessToken) sau khi login. Theo mặc định thì hàm này chỉ link khi acc Facebook đó không link với acc PlayFab nào khác, nếu có thì nó sẽ chặn. Nhưng hàm PlayFabClientAPI.LinkFacebookAccount có thêm argument ForceLink để bạn force link 2 acc dù đã có link trước đó (nhằm mục đích test).

PlayFab cũng cung cấp API Get PlayFab IDs From Facebook IDs cũng có sẵn hàm PlayFabClientAPI.GetPlayFabIDsFromFacebookIDs trong SDK. Từ hàm này ta có thể implement system liên quan đến save/load dữ liệu player bằng Facebook ID. Tuy nhiên cách tốt nhất là wrap hàm này trên cloud script của PlayFab bằng một hàm get full info của mỗi friend của user, thay vì gọi ở client.

Blog này không phải 1 tutorial về PlayFab, nên mình nói lướt lướt

5. Hệ thống in-game friends

PlayFab có sẵn các hàm AddFriend, GetFriendsList, RemoveFriend. Tuy nhiên yêu cầu design có thêm tính năng friend request accept/deny, trong khi hệ thống có sẵn của PlayFab chỉ cho kết bạn ngay. Hơn nữa hệ thống này làm việc với Master Player Account ID (id unique giữa mọi game trong cùng một studio trên PlayFab), trong khi Title Player Account ID (id unique trong 1 game trên PlayFab) được hỗ trợ nhiều hàm xử lý hơn.

Giải pháp của mình là luôn lưu data in-game friend trong phần Objects của mỗi Player, lưu danh sách bạn, request gửi đi và request tới dưới dạng Title Player Account ID.

7. Share thành tựu lên Facebook

Yêu cầu của GD là ở vài chỗ có button để screenshot và share lên Facebook với caption định sẵn.

Về screenshot, mình dùng hệ thống có sẵn của Game mình: dùng OnRenderImage trong 1 Camera và dùng Graphics.Blit để đưa Texture của Camera vào một Texture khác.

Về phần share lên Facebook, mình lưu screenshot thành file trong Application.temporaryCachePath, rồi share hình đó thông qua FileProvider. FileProvider là 1 thứ cho phép mình share file giữa các app với nhau trong Android bằng các URI. Doc về FileProvider: https://developer.android.com/reference/androidx/core/content/FileProvider

Trong Assets/Plugins/Android, tạo thư mục MyGameShare.androidlib với các file:

project.properties: File này chủ yếu nói cho Unity biết thư mục này là một Android library, không phải một app riêng:

target=android-9
android.library=true

AndroidManifest.xml: Để khai báo FileProvider của mình, có authority là ${applicationId}.mygamefileprovider (authority là tên unique của provider). Và có link tới resource xml/file_paths bên dưới.

<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    package="com.zombiefire.share"
    android:versionCode="1"
    android:versionName="1.0">

    <application>
        <provider
            android:name="androidx.core.content.FileProvider"
            android:authorities="${applicationId}.mygamefileprovider"
            android:exported="false"
            android:grantUriPermissions="true">
            <meta-data
                android:name="android.support.FILE_PROVIDER_PATHS"
                android:resource="@xml/file_paths" />
        </provider>
    </application>
</manifest>

res/xml/file_paths.xml: Định nghĩa những nơi mà FileProvider có thể truy cập, ở đây bao gồm các nơi như là Application.temporaryCachePath, Application.persistentDataPath của Unity. 2 giá trị đó của Unity có thể thay đổi tùy theo device nên file này liệt kê hết các chỗ mà 2 giá trị đó có thể rơi vào.

<?xml version="1.0" encoding="utf-8"?>
<paths xmlns:android="http://schemas.android.com/apk/res/android">
    <cache-path name="internal_cache" path="." />
    <external-cache-path name="external_cache" path="." />
    <files-path name="internal_files" path="." />
    <external-files-path name="external_files" path="." />
    <external-path name="external_storage" path="." />
</paths>
Trong project: 
public void ShareImageOutsideGame(string imagePath, string text)
{
    using (AndroidJavaClass unityPlayer = new AndroidJavaClass("com.unity3d.player.UnityPlayer"))
    using (AndroidJavaObject currentActivity = unityPlayer.GetStatic<AndroidJavaObject>("currentActivity"))
    {
        string authority = currentActivity.Call<string>("getPackageName") + ".zf2fileprovider";

        // lấy reference tới file, tạo URI cho nó thông qua FileProvider mà mình tạo
        using (AndroidJavaObject fileObject = new AndroidJavaObject("java.io.File", imagePath))
        using (AndroidJavaClass fileProviderClass = new AndroidJavaClass("androidx.core.content.FileProvider"))
        using (AndroidJavaObject uriObject = fileProviderClass.CallStatic<AndroidJavaObject>("getUriForFile", currentActivity, authority, fileObject))
        
        // tạo intent mới với ACTION_SEND
        using (AndroidJavaClass intentClass = new AndroidJavaClass("android.content.Intent"))
        using (AndroidJavaObject intentObject = new AndroidJavaObject("android.content.Intent", intentClass.GetStatic<string>("ACTION_SEND")))
        {
            intentObject.Call<AndroidJavaObject>("setType", "image/*");
            intentObject.Call<AndroidJavaObject>("putExtra", intentClass.GetStatic<string>("EXTRA_STREAM"), uriObject);
            if (!string.IsNullOrEmpty(text))
                intentObject.Call<AndroidJavaObject>("putExtra", intentClass.GetStatic<string>("EXTRA_TEXT"), text);

            // trao quyền đọc URI cho intent
            int flagGrantRead = intentClass.GetStatic<int>("FLAG_GRANT_READ_URI_PERMISSION");
            intentObject.Call<AndroidJavaObject>("addFlags", flagGrantRead);

            // tạo chooser để gửi giống như Invite friends
            using (AndroidJavaObject chooser = intentClass.CallStatic<AndroidJavaObject>("createChooser", intentObject, DUtil.GetString(5000586)))
            {
                chooser.Call<AndroidJavaObject>("addFlags", flagGrantRead);   // cũng trao quyền cho chooser
                currentActivity.Call("startActivity", chooser);
            }
        }
    }
}

a. Share sheet

Đầu tiên nó import thêm UIKit.h và thêm 1 dòng prototype lấy view controller của unity: 
#import 
...

extern "C" UIViewController* UnityGetGLViewController();
Sau đó nó thêm hàm để hiện share sheet của iOS (giống chooser ACTION_SEND bên Android) bên trên view controller của Unity: 
static void PresentShareSheet(NSArray* items)
{
    if (items == nil || items.count == 0) {
        NSLog(@"PresentShareSheet: nothing to share");
        return;
    }

    // chạy trên main thread vì liên quan UIKit
    dispatch_async(dispatch_get_main_queue(), ^{
        UIViewController* root = UnityGetGLViewController();
        if (root == nil) {
            NSLog(@"PresentShareSheet: no root view controller");
            return;
        }

		// tạo share sheet bao gồm các items để gửi
        UIActivityViewController* avc =
            [[UIActivityViewController alloc] initWithActivityItems:items applicationActivities:nil];

        // Dành cho iPad, nếu không có sourceView thì popoverPresentationController không có anchor và game bị crash
        if (avc.popoverPresentationController != nil) {
            avc.popoverPresentationController.sourceView = root.view;
            avc.popoverPresentationController.sourceRect = CGRectMake(
                root.view.bounds.size.width / 2.0,
                root.view.bounds.size.height / 2.0, 0, 0);
            avc.popoverPresentationController.permittedArrowDirections = 0;
        }

		// hiện share sheet avc thành 1 modal (presentViewController) bên trên unity view hiện tại (root) 
        [root presentViewController:avc animated:YES completion:nil];
    });
}

void _ShareTextOutsideGame(const char* text)
{
    NSString* str = text != NULL ? [NSString stringWithUTF8String:text] : nil;
    if (str.length == 0) {
        NSLog(@"_ShareTextOutsideGame: empty text");
        return;
    }
    PresentShareSheet(@[str]);
}
Note: Vấn đề tin nhắn tách làm 2 và có mp:, ms: không bị trên iOS, nên không cần phải tự tách làm 2 tin nhắn như bên Android.

    NSMutableArray* items = [NSMutableArray array];

    if (path.length > 0 && [[NSFileManager defaultManager] fileExistsAtPath:path]) {
        UIImage* image = [UIImage imageWithContentsOfFile:path];
        if (image != nil)
            [items addObject:image];
        else
            NSLog(@"_ShareImageWithCaption: failed to load image at %@", path);
    }
    if (text.length > 0)
        [items addObject:text];

    PresentShareSheet(items);
}
