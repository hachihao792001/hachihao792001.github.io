Bắt đầu chuyển Hanvas Engine sang WebGL

Sau 2 blog WebGL "cơ bản", ta đã biết đủ các thứ để có thể vẽ được nhiều vật thể bằng GPU: vertex buffer, index buffer, VAO, uniform, dùng ma trận trong vertex shader, depth test, face culling. Blog này mình sẽ dùng đúng chừng đó kiến thức để chuyển bản cuối cùng của series trước, htmlPreview53 ở blog #15, sang WebGL.

Trước hết thì engine đó có khá nhiều thứ mà ta chưa biết làm trên GPU: chế độ ASCII, shadow, texture, ánh sáng. Cho nên mình làm theo 2 giai đoạn:
  1. Dọn dẹp: Xóa hết những thứ trên, nhưng vẫn là Software Rasterizer.
  2. Chuyển: Khi engine chỉ còn những thứ ta biết làm, mới từ từ convert sang WebGL.
Như vậy thì khi bạn xem Diff của các version nó sẽ clean hơn. Những thứ bị xóa sẽ quay lại ở các blog sau, mỗi thứ 1 blog, giống thứ tự của series trước.

Vì blog này có khá nhiều htmlPreview, mà phần lớn là software rasterizer chạy bằng CPU, nên mình để mặc định là disable hết. Ấn Enable để chạy bản bạn muốn xem.

2. Dọn dẹp

a. Bỏ ASCII

Vì engine cũ là Software Rasterizer nên ta có full quyền điều khiển từng pixel, nên chế độ ASCII chỉ đơn giản là lấy màu của từng pixel trong imageData rồi đổi thành ký tự. Với WebGL thì màu của pixel nằm trên GPU, muốn đọc về CPU phải dùng hàm riêng. Nên ta tạm thời bỏ nó, bỏ những thứ sau: checkbox ASCII, ô chỉnh ASCII resolution, tag asciiParagraph, nút "look around (ASCII)", nhánh ASCII trong drawCall, và hàm grayScale01 của Color (chỉ ASCII dùng).

b. Bỏ shadow

Việc build shadow map là một lần render riêng từ góc nhìn của đèn. Sounds complicated on GPU, nên ta bỏ luôn, bỏ các thứ sau: các hằng số shadowMapSize, shadowBias, shadowMapDistance, phần shadow trong DirectionalLight (buildShadowMap, isInShadow, view/projection matrix của đèn), Mat4x4.Orthographic và Camera.getFrustumCenter (chỉ shadow dùng), shadowFactor trong vòng lặp pixel, và checkbox Shadow.

c. Bỏ texture

Bỏ: class Texture, 2 texture mà ta xài, tham số texture của GameObject, và đoạn lấy màu từ texture trong vòng lặp pixel. Màu của pixel bây giờ là màu của tam giác nhân với ánh sáng.

Mình vẫn giữ UV trong dữ liệu của mesh (Triangle.uv, phần đọc vt trong file obj). Nó chỉ là dữ liệu, và sau này ở blog texture ta cũng sẽ cần lại nó.

d. Bỏ ánh sáng

Muốn tính ánh sáng trên GPU thì shader phải có pháp tuyến và vị trí thế giới của từng pixel, thật ra làm luôn cũng được, nhưng mình dành cho nó 1 blog riêng cho nó gọn. Bỏ những thứ sau: DirectionalLight, ambientLight, maxActiveLights, 4 thanh trượt ánh sáng, đoạn xoay đèn trong updateGameObjectTransforms, và toàn bộ phần tính ánh sáng trong vòng lặp pixel.

Kéo theo đó là những thứ chỉ tồn tại để phục vụ ánh sáng: Triangle.worldVertices (vị trí thế giới của 3 đỉnh, dùng để nội suy vị trí thế giới của pixel), getWorldNormal, getPointLightsThatCanAffectTri, MathExtend.hypotSquare. Vòng lặp pixel bây giờ chỉ còn depth test và ghi màu: 
if (z < depthBuffer[pixelIndex]) {
	depthBuffer[pixelIndex] = z;

	const colorIndex = pixelIndex * 4;
	screenBuffer[colorIndex] = triColor.r;
	screenBuffer[colorIndex + 1] = triColor.g;
	screenBuffer[colorIndex + 2] = triColor.b;
}
2 cục cube nhỏ đánh dấu vị trí point light thì mình giữ lại, chúng chỉ là GameObject bình thường.

3. Chuyển sang WebGL

Engine bây giờ chỉ còn: GameObject, Transform, Mesh (Cube và ObjMesh), Camera, và software rasterizer. It's time to convert it to WebGL 😳

a. Context, shader, program

Đổi context, rồi thêm shader và program y như blog 1: 
const gameCanvas = (document.getElementById("gameCanvas"));
const gl = (gameCanvas.getContext("webgl2"));		// <--------------------------

const vertexShaderSource = `#version 300 es
in vec3 aPosition;
uniform mat4 uModel;
uniform mat4 uView;
uniform mat4 uProjection;

void main(){
	gl_Position = uProjection * uView * uModel * vec4(aPosition, 1.0);
}`;
const fragmentShaderSource = `#version 300 es
precision highp float;

uniform vec3 uColor;
out vec4 outColor;

void main(){
	outColor = vec4(uColor, 1.0);
}`;
...
  • Vertex shader bây giờ có đủ cả 3 ma trận Model, View, Projection, đúng như dòng cuối của blog 2: chỉ còn thiếu View matrix ở giữa, giờ đã có.
  • Màu của 1 GameObject thì mọi pixel của nó đều như nhau, nên mình để nó là 1 uniform uColor nằm trong fragment shader. Uniform không chỉ dành cho vertex shader, shader nào khai báo thì shader đó đọc được.
  • Chỉ có 1 attribute aPosition, vì không có ánh sáng hay texture thì đỉnh chưa cần gì khác.
Ta cũng bật thêm depth test, backface culling và set màu clear screen: 
gl.enable(gl.DEPTH_TEST);
gl.enable(gl.CULL_FACE);
gl.frontFace(gl.CW);		// quy ước cùng chiều kim đồng hồ của series trước (blog 2, phần 11)
gl.clearColor(240 / 255, 240 / 255, 240 / 255, 1);		// bằng màu 0xfff0f0f0 mà clearScreen() dùng

b. Ma trận

Mat4x4.Projection của series trước đưa z về [0; 1], mà như ta biết ở blog 2 là WebGL nhận vào [-1; 1]. Nên ta copy hàm Mat4x4.Projection mà ta đã sửa ở blog trước vào: 
class Mat4x4 {
	...

	static Projection(fov, h, w, zNear, zFar) {
		let fovMultiplier = 1.0 / Math.tan(((fov * 0.5) / 180.0) * Math.PI);
		let matrix = new Mat4x4();
		matrix.m[0][0] = (h / w) * fovMultiplier;
		matrix.m[1][1] = fovMultiplier;
		matrix.m[2][2] = (zFar + zNear) / (zFar - zNear);			// series trước: zFar / (zFar - zNear)
		matrix.m[2][3] = (-2 * zFar * zNear) / (zFar - zNear);		// series trước: -zNear * zFar / (zFar - zNear)
		matrix.m[3][2] = 1.0;
		return matrix;
	}
	...
}
Mình thêm lại 3 hàm của blog 2: Multiply, Rotation(q) và toColumnMajor: 
static Multiply(m1, m2) {
	let result = new Mat4x4();
	for (let r = 0; r < 4; r++) {
		for (let c = 0; c < 4; c++) {
			result.m[r][c] = m1.m[r][0] * m2.m[0][c] + m1.m[r][1] * m2.m[1][c] + m1.m[r][2] * m2.m[2][c] + m1.m[r][3] * m2.m[3][c];
		}
	}
	return result;
}

static Rotation(q) {
	const right = q.rotateVector(new Vector3(1, 0, 0));
	const up = q.rotateVector(new Vector3(0, 1, 0));
	const forward = q.rotateVector(new Vector3(0, 0, 1));

	const result = new Mat4x4();
	result.m[0][0] = right.x;
	result.m[0][1] = up.x;
	result.m[0][2] = forward.x;
	result.m[1][0] = right.y;
	result.m[1][1] = up.y;
	result.m[1][2] = forward.y;
	result.m[2][0] = right.z;
	result.m[2][1] = up.z;
	result.m[2][2] = forward.z;
	result.m[3][3] = 1;

	return result;
}

toColumnMajor() {
	let array = new Float32Array(16);
	for (let c = 0; c < 4; c++)
		for (let r = 0; r < 4; r++)
			array[c * 4 + r] = this.m[r][c];
	return array;
}
Có chúng thì Transform tính được Model matrix: 
getModelMatrix() {
	let model = Mat4x4.Multiply(Mat4x4.Rotation(this.rotation), this.getScaleMatrix());
	return Mat4x4.Multiply(this.getTranslationMatrix(), model);
}
Thứ tự scale → rotation → position y hệt getTransformedTriangles của GameObject, và vì getScaleMatrix, rotation, getTranslationMatrix đều dùng giá trị ở world space (lossyScale, rotation đã nhân với cha, position đã đi qua cha), nên hệ thống cha con vẫn hoạt động như cũ.

Còn View matrix thì không cần làm gì: camera.getViewMatrix() đã có sẵn từ blog #7 series trước, trước giờ nó được nhân vào từng tam giác trên CPU, bây giờ chỉ cần gửi nó lên shader.

c. Đưa mesh vào GPU

Mỗi Mesh có 1 vertex buffer và 1 VAO của riêng nó, mình viết riêng 1 hàm uploadToGPU để đưa dữ liệu của nó vào GPU. Hàm này sẽ được gọi ở constructor để nó có sẵn dữ liệu GPU, và hàm setTriangles để nó cập nhật dữ liệu: 
class Mesh {
	constructor(tris = []) {
		this.tris = tris;
		this.vertexCount = 0;
		this.vertexArray = null;
		this.uploadToGPU();		// <-----------------------
	}

	setTriangles(tris, color = new Color(255, 255, 255)) {
		this.tris = [];
		for (let tri of tris) {
			this.tris.push(
				new Triangle(
					[tri.vertices[0].clone(), tri.vertices[1].clone(), tri.vertices[2].clone()],
					[tri.uv[0].clone(), tri.uv[1].clone(), tri.uv[2].clone()],
					color,
				),
			);
		}
		this.uploadToGPU();		// <-----------------------
	}
	
	uploadToGPU() {
		if (this.tris.length == 0) return;

		const vertexData = new Float32Array(this.tris.length * 9);		// mỗi tam giác 3 đỉnh, mỗi đỉnh 3 float
		for (let i = 0; i < this.tris.length; i++) {
			for (let j = 0; j < 3; j++) {
				const vertex = this.tris[i].vertices[j];
				vertexData[i * 9 + j * 3] = vertex.x;
				vertexData[i * 9 + j * 3 + 1] = vertex.y;
				vertexData[i * 9 + j * 3 + 2] = vertex.z;
			}
		}
		this.vertexCount = this.tris.length * 3;

		this.vertexArray = gl.createVertexArray();
		gl.bindVertexArray(this.vertexArray);

		const vertexBuffer = gl.createBuffer();
		gl.bindBuffer(gl.ARRAY_BUFFER, vertexBuffer);
		gl.bufferData(gl.ARRAY_BUFFER, vertexData, gl.STATIC_DRAW);

		gl.enableVertexAttribArray(aPosition);
		gl.vertexAttribPointer(aPosition, 3, gl.FLOAT, false, 12, 0);

		gl.bindVertexArray(null);
	}
}
Lần này mình dùng drawArrays chứ không dùng index buffer như blog 1. Mesh của engine là một danh sách tam giác, mỗi tam giác 3 đỉnh riêng, nên chưa có index để dùng. Gom các đỉnh trùng nhau lại thành index buffer là việc tối ưu để sau.

Ngoài ra, cubeMesh được ground và 2 cube point light dùng chung, nên chỉ có 1 VAO cho cả 3, giống phần 12 của blog 2: cùng 1 VAO, mỗi lần vẽ đổi uModel.

d. GameObject tự vẽ chính nó

GameObject có thêm 2 hàm, thay cho getTransformedTriangles và getTransformedTrianglesWithChildren: 
class GameObject {
	...

	draw() {
		if (this.mesh.vertexCount == 0) return;		// ObjMesh chưa tải xong
		gl.uniformMatrix4fv(uModel, false, this.transform.getModelMatrix().toColumnMajor());		// truyền model matrix
		gl.uniform3f(uColor, this.color.r / 255, this.color.g / 255, this.color.b / 255);			// truyền màu
		gl.bindVertexArray(this.mesh.vertexArray);
		gl.drawArrays(gl.TRIANGLES, 0, this.mesh.vertexCount);
	}

	drawWithChildren() {
		this.draw();
		for (let child of this.transform.children) {
			if (child.gameObject != null) {
				child.gameObject.drawWithChildren();
			}
		}
	}
}

e. Đưa projection, view matrix vào và hàm render cuối

Ở engine cũ, có 2 chỗ mà tính projection matrix: lúc khởi tạo, và lúc đổi resolution. Bây giờ ta chỉ cần thêm 1 hàm để truyền projection matrix đó vào GPU:

	gameCanvas.height = canvasRenderHeight;

Có hết mọi thứ rồi, đây chính là hàm render cuối của chúng ta, hàm này truyền luôn view matrix vào GPU: 
function render() {
	gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT);
	gl.uniformMatrix4fv(uView, false, camera.getViewMatrix().toColumnMajor());	// truyền view matrix vào GPU

	ground.drawWithChildren();
	for (let light of pointLights) {
		light.drawWithChildren();
	}
	woodTower.drawWithChildren();
}
6 dòng gọi hàm trong update được thay bằng: 
updateGameObjectTransforms();
render();
So với pipeline ở phần 1, những việc sau bây giờ do GPU làm, ta không phải viết dòng nào:
  • Chuyển đỉnh từ object space sang world, view, clip space: vertex shader nhân 3 ma trận.
  • Backface culling: gl.CULL_FACE, thay cho cái tích vô hướng trong worldSpaceToViewSpace.
  • Cắt tam giác theo near plane (clipAgainstPlane của blog #7 series trước): GPU tự clip.
  • Perspective divide và nhân ra kích thước canvas (kèm đổi dấu y).
  • Toàn bộ vòng lặp pixel: bounding box, edge function, nội suy z, depth buffer.

5. Đổi resolution và gl.viewport

Ở blog 1 phần 6 mình có nói gl.viewport mặc định bằng kích thước canvas lúc tạo context. Chữ "lúc tạo context" là chỗ quan trọng: đổi gameCanvas.width sau đó thì drawing buffer đổi theo, nhưng viewport thì không. Ví dụ mình đổi resolution thành 300x225, thì canvas đổi thành 300x255, nhưng WebGL vẫn đang render ra 600x450. GPU vẫn kéo [-1; 1] ra 600x450 pixel, nên chỉ có phần nằm trong 300x225 pixel đầu tiên (tính từ góc dưới trái, vì trục y của WebGL hướng lên) là hiện ra.

Sửa bằng 1 dòng trong updateRenderResolution: 
function updateRenderResolution() {
	gameCanvas.width = canvasRenderWidth;
	gameCanvas.height = canvasRenderHeight;

	projectionMatrix = Mat4x4.Projection(fov, gameCanvas.height, gameCanvas.width, znear, zfar);
	gl.uniformMatrix4fv(uProjection, false, projectionMatrix.toColumnMajor());
	gl.viewport(0, 0, gameCanvas.width, gameCanvas.height);		// <--------------------------
}
Ở software rasterizer, việc này nằm trong rasterizer.updateResolution, nó cấp phát lại screen buffer và depth buffer. Với WebGL thì 2 buffer đó do trình duyệt cấp phát lại khi canvas đổi kích thước, phần của ta chỉ còn viewport.
