Tái cấu trúc code

Xong blog 13 rồi thì engine đã chạy nhanh hơn nhiều, nhưng nó lại đồng thời khó đọc hơn 😅. Blog này sẽ tái cấu trúc lại engine "1 chút" cho nó có lại tí readability (thật ra là do mình muốn thống nhất nó về repo Hanvas Engine).

1. Gom nhóm các class

Ở Hanvas Engine mình đã tách các class ra thành các file js modules, các class chung 1 "loại" sẽ nằm chung file, cụ thể:
  • math.js: Các class thuần toán học như Vector2, Vector3, Mat4x4, Quaternion, Plane (và vài class khác mình tạo thêm trong blog này)
  • graphics.js: Các class về đồ họa, chỉ có Color, Texture
  • mesh.js: Class Mesh và các class con Triangle, Cube, ObjMesh
  • engine.js: Các class liên quan tới game engine: Camera, GameObject, DirectionalLight, Rasterizer
  • index.js: các biến liên quan tới scene + game loop + mấy cái listener
Mục đích của phần này là xếp lại các class, sao cho những class chung 1 "loại" thì nằm kế nhau, sau đó phân cách các phần bằng 1 comment.

Nhân tiện mình dọn luôn mấy thứ chết trong file:
  • edgePlanes: 4 cái mặt phẳng để clip theo 4 cạnh màn hình, viết từ blog 7, và từ blog 8 tới giờ không ai gọi tới (vì rasterizer đã tự giới hạn trong bounding box rồi).
  • Đoạn code dùng phím I, K, J, L, U, O để di chuyển point light: cái đó chỉ để test, không phải một phần của engine.
  • Đổi tên biến canvas thành gameCanvas, vì lát nữa trong Texture còn một cái canvas tạm nữa, hai cái trùng tên đọc rất dễ nhầm.

2. MathExtend và BoundingBox

Hai hàm global edgeFunction và hypotSquare đó giờ không có nơi nương thân. Cho nên giờ mình tạo class mới MathExtend để chứa tụi nó: 
class MathExtend {
	static edgeFunction(v0, v1, p) {
		return (v0.y - v1.y) * (p.x - v0.x) + (v1.x - v0.x) * (p.y - v0.y);
	}

	static hypotSquare(ax, ay, az, bx, by, bz) { ... }
}
Thứ hai là cái Triangles.boundingBox(). Từ blog 8 tới giờ nó trả về một mảng 4 phần tử, và chỗ dùng thì đọc như thế này: 
const bbox = tri.boundingBox(canvasWidth, canvasHeight);
...
for (let y = bbox[2]; y <= bbox[3]; y++) {
	for (let x = bbox[0]; x <= bbox[1]; x++) {
		...
	}
}
Mình là người viết, nên mình quen 0, 1 là min x max x; 2, 3 là min y, max y. Nhưng người khác đọc vào thì chả khác gì magic number. Cho nên mình tạo riêng luôn 1 class cho bounding box: 
class BoundingBox {
	constructor(minX, maxX, minY, maxY) {
		this.minX = minX;
		this.maxX = maxX;
		this.minY = minY;
		this.maxY = maxY;
	}

	isValid() {
		return this.minX <= this.maxX && this.minY <= this.maxY;
	}

	static union(bbox1, bbox2) {
		return new BoundingBox(
			Math.min(bbox1.minX, bbox2.minX),
			Math.max(bbox1.maxX, bbox2.maxX),
			Math.min(bbox1.minY, bbox2.minY),
			Math.max(bbox1.maxY, bbox2.maxY),
		);
	}

	static intersect(bbox1, bbox2) {
		return new BoundingBox(
			Math.max(bbox1.minX, bbox2.minX),
			Math.min(bbox1.maxX, bbox2.maxX),
			Math.max(bbox1.minY, bbox2.minY),
			Math.min(bbox1.maxY, bbox2.maxY),
		);
	}

	static isOverlap(bbox1, bbox2) {
		return (
			((bbox1.minX < bbox2.maxX && bbox1.maxX > bbox2.minX) || (bbox2.minX < bbox1.maxX && bbox2.maxX > bbox1.minX)) &&
			((bbox1.minY < bbox2.maxY && bbox1.maxY > bbox2.minY) || (bbox2.minY < bbox1.maxY && bbox2.maxY > bbox1.minY))
		);
	}
}
Code sẽ trở nên dễ đọc hơn: 
for (let y = bbox.minY; y <= bbox.maxY; y++) {
	for (let x = bbox.minX; x <= bbox.maxX; x++) {

3. MathTriangle và Triangle

Class Triangle bây giờ đang khá là bloat, ngoài chứa những biến, hàm phục vụ engine ra, thì nó cũng có những hàm thuần toán học, như getCenter, getNormal, mulMat4x4, ...
Chỗ thấy rõ nhất là shadow map, bạn xem lại hàm buildShadowMap, nó chỉ xài vertices chứ không xài worldVertices hay uv. Những hàm nó xài: mulMat4x4, perspectiveDivide, boundingBox, calculateSignedDoubleArea đều là hàm thuần toán học.

Cho nên ta tách phần toán học ra thành 1 class mới MathTriangle, còn Triangle kế thừa nó và thêm phần engine: 
class MathTriangle {
	constructor(vertices = []) { ... }		// chỉ có vertices và signedDoubleArea
	mulMat4x4(m) { ... }
	rotate(q) { ... }
	getCenter() { ... }
	getNormal() { ... }
	clipAgainstPlane(plane) { ... }			// cắt hình, trả về các MathTriangle mới (thuần toán học)
	boundingBox(maxWidth, maxHeight) { ... }
}

class Triangle extends MathTriangle {
	constructor(vertices = [], uv = [], color = new Color(255, 255, 255)) {
		super(vertices);
		this.uv = uv;
		this.viewDistanceSquared = 0;
		this.worldVertices = [...];
		this.color = color;
		this.texture = null;
	}

	clipAgainstPlane(plane) { ... }			// cắt hình VÀ nội suy uv, worldVertices
	getWorldNormal() { ... }
	getPointLightsThatCanAffectTri(...) { ... }
}
Để ý là clipAgainstPlane có ở cả hai. Bản ở MathTriangle chỉ cắt toạ độ - đủ dùng cho mấy phép toán hình học. Bản ở Triangle override nó, vì khi cắt một tam giác có texture thì hai đỉnh mới sinh ra còn phải được nội suy uv và toạ độ world nữa (xem lại blog 10).

Và cái shadow map giờ khai báo đúng thứ nó cần: 
this.shadowTri = new MathTriangle();
Tiện tay mình khai báo sẵn viewMatrix và projectionMatrix trong constructor của DirectionalLight luôn (blog 9 mình thiếu), cho javascript đỡ phải suy diễn class ngầm.

4. Transform

Vấn đề:
  • Camera có pos và rotation.
  • GameObject cũng có pos, rotation và scale.
Nếu bạn từng xài Unity hay game engine khác, thì bạn biết là những thứ này có thể được gom trong 1 class riêng là Transform, là tổng hợp những "Phép biến hình" trước khi đưa nó qua view matrix (y hệt cách mình giải thích model matrix trong blog 4).

Mà đã làm Transform rồi, thì mình cũng phải làm luôn hệ thống parent - child giống trong Unity: Parent di chuyển, xoay, phóng to thì child cũng phải di chuyển, xoay, phóng to theo.

a. Các biến, hàm cơ bản

Với mô tả như trên thì constructor của class Transform sẽ có dạng như sau: 
class Transform {
	constructor(localPosition, localEulerAngles, localScale, name) {	// có name để dễ phân biệt
		this.localPosition = localPosition;
		this.localRotation = Quaternion.buildQuaternionEuler(localEulerAngles);
		this.localScale = localScale;

		this._parent = null;		// có dấu gạch dưới vì ta phải xem nó là private (có lí do)
		this._children = [];		// có dấu gạch dưới vì ta phải xem nó là private (có lí do)
		this.gameObject = null;		// reference về lại gameObject chứa nó, như Unity
	}
	...
	clone() {
		let t = new Transform(this.localPosition.clone(), Vector3.zero, this.localScale.clone(), this.name);
		t.localRotation = new Quaternion(this.localRotation.a, this.localRotation.b, this.localRotation.c, this.localRotation.d);
		return t;
	}
	...
}
Đầu tiên, lí do ta lưu local thay vì world là vì để đỡ phải tính lại position, rotation, scale của Transform hiện tại mỗi lần parent của nó di chuyển. Từ local ta mới tính ngược lại world khi cần, ngoài ra thì ta cũng phải thêm hàm để set world rồi chuyển lại local: 
get position() {
	if (this._parent == null) return this.localPosition;
	return this._parent.transformPoint(this.localPosition);
}

get rotation() {
	if (this._parent == null) return this.localRotation;
	return Quaternion.multiply(this._parent.rotation, this.localRotation);
}

get lossyScale() {		// scale thế giới, đặt tên vậy cho giống Unity, sẽ giải thích sau
	if (this._parent == null) return this.localScale;
	return Vector3.scale(this._parent.lossyScale, this.localScale);
}

set position(worldPosition) {
	this.localPosition = this._parent == null ? worldPosition : this._parent.inverseTransformPoint(worldPosition);
}

set rotation(worldRotation) {
	//conjugate() (liên hợp) của một quaternion đơn vị chính là nghịch đảo của quaternion đó (blog 6)
	// dùng conjugate để "xoay ngược lại" world thành local (hope that make sense)
	this.localRotation = this._parent == null ? worldRotation : Quaternion.multiply(this._parent.rotation.conjugate(), worldRotation);
}

// không có set lossyScale như Unity (có lí do), cho set vào localScale là đủ
Các hàm trên có xài hàm transformPoint và inverseTransformPoint nên ta phải tạo luôn. Lúc mình học Unity, mình luôn nhớ hàm Transform.TransformPoint là "convert từ local sang world". Còn khi đã quen với engine này, thì bạn có thể hiểu nó là "hàm getTransformedTriangles, nhưng thay vì tính với mọi tam giác trong GameObject, thì chỉ tính với 1 điểm". Hàm getTransformedTriangles ta áp dụng thứ tự scale -> rotate -> translate, ở đây ta cũng làm vậy: 
transformPoint(point) {
	return Vector3.add(this.position, this.rotation.rotateVector(Vector3.scale(point, this.lossyScale)));
}

// inverseTransformPoint thì ngược lại: translate -> rotate -> scale
inverseTransformPoint(point) {
	// inverseRotateVector mình có giải thích ở blog Portal
	let local = this.rotation.inverseRotateVector(Vector3.sub(point, this.position));
	let scale = this.lossyScale;
	return new Vector3(local.x / scale.x, local.y / scale.y, local.z / scale.z);
}

b. Hàm setParent

Lí do tại sao _parent và _children lại phải được xem là private: vì quan hệ cha-con được lưu ở hai nơi: thằng con giữ con trỏ lên cha (_parent), và thằng cha giữ danh sách con (_children). Nếu bạn gán tay a._parent = b mà quên b._children.push(a) thì sẽ gặp vấn đề ngay.

Cho nên hai biến này chỉ được truy cập trong những hàm có liên quan tới quan hệ cha con giữa nhiều Transform, và chỉ có hàm setParent là làm như vậy.

Hàm này có dạng setParent(parent, worldPositionStays = true), worldPositionStays nghĩa là "đổi cha nhưng Transform đứng yên tại chỗ". Hàm sẽ có ý tưởng cơ bản như sau:
  1. Check nếu parent mới trùng parent cũ thì bỏ
  2. Check nếu parent mới là hậu duệ của Transform hiện tại (gây vòng lặp vô tận) thì bỏ
  3. Cache lại position, rotation, scale thế giới trước khi cập nhật parent
  4. Gỡ Transform hiện tại khỏi parent cũ (nếu có)
  5. Gắn vào parent mới (nhớ set luôn _children của parent)
  6. Nếu worldPositionStays=true thì trả lại position, rotation, scale cũ
setParent(parent, worldPositionStays = true) {
	if (parent === this._parent) return;
	if (parent != null && parent.isDescendantOf(this)) {
		console.warn("Cannot parent " + this.name + " to " + parent.name + ": that would make a cycle");
		return;
	}

	let worldPosition = this.position;		// cache lại world trước khi cập nhật parent
	let worldRotation = this.rotation;
	let worldScale = this.lossyScale;

	if (this._parent != null) {				// gỡ khỏi parent cũ nếu có
		let index = this._parent._children.indexOf(this);
		if (index >= 0) this._parent._children.splice(index, 1);
	}

	this._parent = parent;					// gắn vào parent mới, cả 2 chiều
	if (parent != null) parent._children.push(this);

	if (worldPositionStays) {
		this.position = worldPosition;		// setter sẽ tự đổi về local của cha mới
		this.rotation = worldRotation;
		let parentScale = parent != null ? parent.lossyScale : Vector3.one;
		this.localScale = new Vector3(worldScale.x / parentScale.x, worldScale.y / parentScale.y, worldScale.z / parentScale.z);
	}
}

d. Những hàm bổ trợ khác

Đã số những hàm trong đây khá là hiển nhiên và dễ hiểu, hàm nào cần suy nghĩ chút thì mình thêm comment.

Các hàm liên quan tới quan hệ cha - con: 
get parent() {
	return this._parent;
}

set parent(parent) {
	this.setParent(parent);
}

get children() {
	return this._children;
}

get childCount() {
	return this._children.length;
}

get root() {
	let current = this;
	while (current._parent != null) {
		current = current._parent;
	}
	return current;
}

setParent(parent, worldPositionStays = true) {...} // đã giải thích

isDescendantOf(parent) {
	let current = this;
	while (current != null) {
		if (current === parent) return true;
		current = current._parent;
	}
	return false;
}

getChild(index) {
	return this._children[index];
}

detachChildren() {
	for (let child of this._children.slice()) {
		child.setParent(this._parent);
	}
}
Các hàm lấy hướng local: 
getForward() {
	return this.rotation.rotateVector(Vector3.forward).normalize();
}

getRight() {
	return this.rotation.rotateVector(Vector3.right).normalize();
}

getUp() {
	return this.rotation.rotateVector(Vector3.up).normalize();
}
Các hàm thay đổi position, rotation theo cách khác nhau ngoài việc set thẳng: 
translate(offset) {
	this.position = Vector3.add(this.position, offset);
}

translateLocal(offset) {
	this.position = Vector3.add(this.position, this.rotation.rotateVector(offset));
}

rotate(eulerX, eulerY, eulerZ) {
	let q = Quaternion.buildQuaternionEuler(new Vector3(eulerX, eulerY, eulerZ));
	this.rotation = Quaternion.multiply(q, this.rotation);
}

rotateAround(axis, angle) {	// lợi dụng hàm buildQuaternionAxisAngle
	this.rotation = Quaternion.multiply(Quaternion.buildQuaternionAxisAngle(axis, angle), this.rotation);
}

setEulerAngles(eulerAngles) {
	this.rotation = Quaternion.buildQuaternionEuler(eulerAngles);
}

setLocalEulerAngles(eulerAngles) {
	this.localRotation = Quaternion.buildQuaternionEuler(eulerAngles);
}

lookRotation(forward, up = Vector3.up) {
	this.rotation = Quaternion.lookRotation(forward, up);	// đã giải thích ở blog Portal
}

lookAt(target, up = Vector3.up) {
	this.lookRotation(Vector3.sub(target, this.position).normalize(), up);
}
Hàm lookRotation kéo theo một mớ hàm toán: Quaternion.lookRotation, Quaternion.buildQuaternionAxisRadian, Vector3.projectVectorToPlane, Vector3.getAxisAndRadianBetween, Vector3.getRadianBetweenWithAxis. Mấy hàm này mình đã giải thích kĩ trong blog portal (phần dựng lookRotation để chỉnh lại roll của player sau khi teleport), nên ở đây mình không nói lại nữa.

Các hàm về ma trận: 
getScaleMatrix() {
	let scale = this.lossyScale;
	return Mat4x4.Scale(scale.x, scale.y, scale.z);
}

getTranslationMatrix() {
	let position = this.position;
	return Mat4x4.Translation(position.x, position.y, position.z);
}

getViewMatrix() {
	return Mat4x4.ViewFromPosRot(this.position, this.rotation);
}
Hàm Mat4x4.ViewFromPosRot bốc từ hàm getViewMatrix của Camera ra: 
static ViewFromPosRot(pos, rotation) {
	let forward = rotation.rotateVector(Vector3.forward);
	let right = rotation.rotateVector(Vector3.right);
	let up = rotation.rotateVector(Vector3.up);
	return Mat4x4.View(right, up, forward, pos);
}
Hàm về chuyển đổi vector: 
transformDirection(direction) {
	return this.rotation.rotateVector(direction);
}

inverseTransformDirection(direction) {
	return this.rotation.inverseRotateVector(direction);
}
Nếu bạn như mình hồi mới học Unity, hay bị lộn giữa TransformPoint và TransformDirection, thì như code bạn đã thấy, TransformDirection kệ position và scale của Transform, chỉ biến đổi theo rotation, vì thứ ta cần biến đổi chỉ là hướng (đại lượng vector).
