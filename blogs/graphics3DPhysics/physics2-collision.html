Va chạm đầu tiên và 3 cách phản hồi

Ở blog trước cái hộp nảy trên một mặt đất giả, chỉ là một dòng if so độ cao với 0.5. Blog này ta làm va chạm thật: một vật biết được nó đang chạm vào vật nào, chạm ở đâu, lún vào bao sâu, rồi phản ứng lại. Mình sẽ bắt đầu với hình dễ nhất là quả cầu, và thử 3 cách phản hồi va chạm khác nhau để xem cái nào chạy được.

Một hệ thống va chạm luôn có 2 nửa tách biệt:
  • Phát hiện va chạm (collision detection): 2 vật có đang chạm nhau không, nếu có thì chạm theo hướng nào, lún sâu bao nhiêu.
  • Phản hồi va chạm (collision response): biết rồi thì làm gì với vận tốc và vị trí của 2 vật.
Blog này phần phát hiện rất đơn giản, phần lớn công sức nằm ở phản hồi.

1. Quả cầu

Engine chưa có mesh hình cầu, nên mình thêm Primitives.sphere(). Cách dựng giống như các đường kinh tuyến, vĩ tuyến trên quả địa cầu: chia quả cầu thành rings vòng từ cực trên xuống cực dưới (góc theta từ 0 tới π), mỗi vòng chia thành segments đoạn quanh trục y (góc phi từ 0 tới 2π). Một điểm cách cực trên một góc theta thì có độ cao 0.5 * cos(theta) và cách trục y một khoảng 0.5 * sin(theta), đi vòng quanh trục y một góc phi thì khoảng cách đó chia ra theo x là nhân cos(phi), theo z là nhân sin(phi), y như tọa độ một điểm trên đường tròn. Mỗi ô giữa 2 vòng và 2 đoạn là một hình tứ giác, cắt ra 2 tam giác: 
class Primitives {
	...
	static sphere(segments = 20, rings = 14) {
		let triangles = [];
		let pointOnSphere = (ring, segment) => {
			let theta = (ring / rings) * Math.PI;
			let phi = (segment / segments) * Math.PI * 2;
			return new Vector3(0.5 * Math.sin(theta) * Math.cos(phi), 0.5 * Math.cos(theta), 0.5 * Math.sin(theta) * Math.sin(phi));
		};
		let uvOnSphere = (ring, segment) => new Vector2(segment / segments, 1 - ring / rings);

		for (let ring = 0; ring < rings; ring++) {
			for (let segment = 0; segment < segments; segment++) {
				let a = pointOnSphere(ring, segment);
				let b = pointOnSphere(ring, segment + 1);
				let c = pointOnSphere(ring + 1, segment + 1);
				let d = pointOnSphere(ring + 1, segment);
				let uvA = uvOnSphere(ring, segment);
				let uvB = uvOnSphere(ring, segment + 1);
				let uvC = uvOnSphere(ring + 1, segment + 1);
				let uvD = uvOnSphere(ring + 1, segment);
				if (ring != 0) triangles.push(new Triangle([a, b, c], [uvA, uvB, uvC]));
				if (ring != rings - 1) triangles.push(new Triangle([a, c, d], [uvA, uvC, uvD]));
			}
		}
		return Mesh.fromTriangles(triangles);
	}
	...
}
  • Bán kính là 0.5, để quả cầu vừa khít trong khối hộp 1x1x1, giống Primitives.cube().
  • Ở vòng đầu tiên (ring == 0), 2 điểm a và b đều nằm ở cực trên (sin 0 = 0), tam giác a, b, c bị dẹp thành một đường thẳng nên mình bỏ qua. Vòng cuối thì c và d trùng nhau ở cực dưới, bỏ tam giác còn lại.
  • UV thì quả bóng đỏ của ta không dùng (không có texture), nhưng Triangle cần có, mình trải ảnh theo kinh độ (u) và vĩ độ (v, cực trên là 1).
  • Thứ tự đỉnh a, b, c là chiều kim đồng hồ khi nhìn từ bên ngoài, đúng với gl.frontFace(gl.CW) mà engine dùng từ series trước, nên các mặt không bị cull mất.
Cái hộp được đổi thành một quả bóng đỏ, các biến box, boxRigidbody, wasBoxGoingUp đổi tên thành ball, ballRigidbody, wasBallGoingUp. Mặt đất giả vẫn chạy được với quả bóng, vì bán kính 0.5 đúng bằng nửa chiều cao của cái hộp cũ. Kết quả:

2. Collider và cách thứ nhất: đẩy ra

Để biết một vật có hình dạng gì khi va chạm, mỗi vật cần thêm một component mô tả hình dạng của nó, gọi là collider. Collider tách riêng với MeshRenderer: mesh dùng để vẽ có thể có hàng nghìn tam giác, còn collider chỉ cần một hình đơn giản bao lấy vật, ví dụ một quả cầu hay một cái hộp. Mình thêm 2 loại collider: 
class Collider extends Component {
	get rigidbody() {
		return this.gameObject.getComponent(Rigidbody);
	}
}

class SphereCollider extends Collider {
	constructor(radius = 0.5) {
		super();
		this.radius = radius;
	}

	get worldRadius() {
		return this.radius * this.transform.lossyScale.x;
	}
}

class BoxCollider extends Collider {
}

class Contact {
	constructor(point, normal, depth) {
		this.point = point;
		this.normal = normal;
		this.depth = depth;
	}
}
  • worldRadius: bán kính sau khi tính scale của GameObject, mình giả sử quả cầu được scale đều 3 trục nên chỉ lấy x.
  • BoxCollider chưa cần thêm gì, kích thước của hộp chính là lossyScale của GameObject (vì mesh hộp có cạnh dài 1).
  • Một vật có collider mà không có Rigidbody là vật tĩnh, không bao giờ di chuyển, như mặt đất. Getter rigidbody trả về undefined cho những vật này.
  • Contact là kết quả của phần phát hiện: điểm chạm, pháp tuyến (normal, vector đơn vị chỉ hướng đẩy 2 vật ra xa nhau), và độ lún (depth, 2 vật đang chồng lên nhau bao sâu). Điểm chạm thì blog này chưa dùng, blog 3 làm cho vật xoay được, rồi tới blog 5 điểm chạm mới cần để làm vật xoay khi va chạm.
Phần phát hiện va chạm giữa quả cầu và mặt đất (là một cái hộp): tìm điểm trên hộp gần tâm quả cầu nhất, nếu khoảng cách từ điểm đó tới tâm nhỏ hơn bán kính thì đang chạm nhau. Với một hộp không bị xoay, điểm gần nhất tìm rất dễ: kẹp từng tọa độ của tâm quả cầu vào khoảng [min, max] của hộp theo trục đó. Ví dụ hộp có x từ -1 tới 1, tâm quả cầu có x = 3 thì điểm gần nhất có x = 1 (mép hộp), còn nếu x của tâm là 0.5 (đã nằm trong khoảng) thì giữ nguyên 0.5. Mỗi trục độc lập với nhau nên làm riêng từng trục là ra điểm gần nhất. 
boxVsSphere(box, sphere) {
	let center = sphere.transform.position;
	let boxCenter = box.transform.position;
	let halfSize = Vector3.div(box.transform.lossyScale, 2);
	let closestPoint = new Vector3(
		Math.max(boxCenter.x - halfSize.x, Math.min(center.x, boxCenter.x + halfSize.x)),
		Math.max(boxCenter.y - halfSize.y, Math.min(center.y, boxCenter.y + halfSize.y)),
		Math.max(boxCenter.z - halfSize.z, Math.min(center.z, boxCenter.z + halfSize.z)),
	);
	let offset = Vector3.sub(center, closestPoint);
	let distance = offset.magnitude();
	if (distance == 0 || distance >= sphere.worldRadius) return null;
	return new Contact(closestPoint, Vector3.div(offset, distance), sphere.worldRadius - distance);
}
Pháp tuyến hướng từ điểm gần nhất ra tâm quả cầu (từ hộp sang cầu), độ lún là bán kính trừ khoảng cách. Trường hợp distance == 0 là khi tâm quả cầu đã lọt hẳn vào trong hộp, lúc đó không biết đẩy ra hướng nào nên mình bỏ qua luôn, coi như không chạm. Hàm này giả sử hộp không bị xoay, blog 4 sẽ nói lại chuyện này.

Lát nữa step sẽ duyệt qua từng cặp collider (A, B) theo thứ tự chúng nằm trong scene, nên ta cần một hàm chọn đúng hàm phát hiện cho từng cặp. Mình quy ước pháp tuyến của Contact luôn hướng từ vật A sang vật B, nên nếu cặp đến theo thứ tự cầu trước hộp sau, ta gọi boxVsSphere với thứ tự đảo lại rồi lật pháp tuyến: 
findContact(colliderA, colliderB) {
	if (colliderA instanceof BoxCollider && colliderB instanceof SphereCollider) return this.boxVsSphere(colliderA, colliderB);
	if (colliderA instanceof SphereCollider && colliderB instanceof BoxCollider) {
		let contact = this.boxVsSphere(colliderB, colliderA);
		if (contact != null) contact.normal = Vector3.mul(contact.normal, -1);
		return contact;
	}
	return null;
}
Giờ tới phần phản hồi. Cách đầu tiên mà ai cũng nghĩ tới: đang lún vào thì đẩy nó ra cho hết lún, rồi bỏ phần vận tốc đang lao vào vật kia đi. Nếu cả 2 vật đều di chuyển được thì mỗi bên chịu một nửa: 
resolveContact(colliderA, colliderB, contact) {
	let rigidbodyA = colliderA.rigidbody;
	let rigidbodyB = colliderB.rigidbody;
	let movableCount = (rigidbodyA != null ? 1 : 0) + (rigidbodyB != null ? 1 : 0);
	let pushDistance = contact.depth / movableCount;

	if (rigidbodyA != null) {
		rigidbodyA.transform.position = Vector3.sub(rigidbodyA.transform.position, Vector3.mul(contact.normal, pushDistance));
		let speedTowardB = Vector3.dot(rigidbodyA.velocity, contact.normal);
		if (speedTowardB > 0) rigidbodyA.velocity = Vector3.sub(rigidbodyA.velocity, Vector3.mul(contact.normal, speedTowardB));
	}
	if (rigidbodyB != null) {
		rigidbodyB.transform.position = Vector3.add(rigidbodyB.transform.position, Vector3.mul(contact.normal, pushDistance));
		let speedTowardA = -Vector3.dot(rigidbodyB.velocity, contact.normal);
		if (speedTowardA > 0) rigidbodyB.velocity = Vector3.add(rigidbodyB.velocity, Vector3.mul(contact.normal, speedTowardA));
	}
}
Pháp tuyến hướng từ A sang B, nên A bị đẩy theo hướng -normal, B theo hướng +normal. Phần vận tốc của A hướng về phía B là tích vô hướng dot(vA, normal) (độ dài hình chiếu của vận tốc lên pháp tuyến), nếu dương tức là A đang lao vào B thì trừ phần đó đi, chỉ giữ lại phần vận tốc song song với mặt chạm. B thì ngược dấu.

Cuối cùng là gắn mọi thứ vào step. Thứ tự bây giờ là: cập nhật vận tốc (trọng lực), xử lý va chạm, rồi mới cập nhật vị trí, nên vòng lặp cũ được tách làm 2. Trọng lực đi trước để phần va chạm thấy luôn lượng vận tốc mà trọng lực vừa cộng vào trong bước này và xóa nó đi nếu vật đang đè lên mặt đất. Cập nhật vị trí đi sau để vật di chuyển bằng vận tốc đã được sửa, chứ không lún thêm một bước nữa rồi mới sửa. Mặt đất giả bị bỏ đi, ta duyệt qua mọi cặp collider: 
step(scene, dt) {
	let rigidbodies = scene.getAllComponentsOfType(Rigidbody);
	for (let rigidbody of rigidbodies) {
		rigidbody.integrateForces(dt, this.gravity);
	}

	let colliders = scene.getAllComponentsOfType(Collider);					// <--------------------- tìm cả class con (instanceof)
	for (let i = 0; i < colliders.length; i++) {								// <---------------------
		for (let j = i + 1; j < colliders.length; j++) {
			if (colliders[i].rigidbody == null && colliders[j].rigidbody == null) continue;
			let contact = this.findContact(colliders[i], colliders[j]);
			if (contact != null) this.resolveContact(colliders[i], colliders[j], contact);
		}
	}

	for (let rigidbody of rigidbodies) {
		rigidbody.integrateVelocity(dt);
	}
}
j bắt đầu từ i + 1 để mỗi cặp chỉ xét 1 lần, và cặp nào cả 2 đều tĩnh (không có Rigidbody) thì bỏ qua. Ground được gắn thêm BoxCollider, quả bóng được gắn SphereCollider. Mình cũng bỏ luôn dòng "Bounce peaks" và hàm updateBouncePeaks, vì quả bóng không còn nảy nữa, và spawnPhysicsObjects không cần lưu ball ra biến ngoài nữa. Kết quả:
Quả bóng rơi xuống và đứng im luôn, không nảy chút nào: vận tốc lao xuống bị xóa sạch ngay khoảnh khắc chạm đất.

3. Nhiều quả cầu

Phát hiện va chạm giữa 2 quả cầu còn dễ hơn: 2 quả chạm nhau khi khoảng cách giữa 2 tâm nhỏ hơn tổng 2 bán kính. 
findContact(colliderA, colliderB) {
	if (colliderA instanceof SphereCollider && colliderB instanceof SphereCollider) return this.sphereVsSphere(colliderA, colliderB);	// <---------------------
	...
}

sphereVsSphere(sphereA, sphereB) {
	let offset = Vector3.sub(sphereB.transform.position, sphereA.transform.position);
	let distance = offset.magnitude();
	let radiusSum = sphereA.worldRadius + sphereB.worldRadius;
	if (distance == 0 || distance >= radiusSum) return null;
	let normal = Vector3.div(offset, distance);
	let point = Vector3.add(sphereA.transform.position, Vector3.mul(normal, sphereA.worldRadius));
	return new Contact(point, normal, radiusSum - distance);
}
Pháp tuyến là hướng từ tâm A sang tâm B, điểm chạm là điểm trên bề mặt A theo hướng đó.

Quanh chỗ thả có 4 bức tường tĩnh (chỉ có BoxCollider, không có Rigidbody) để bóng không lăn đi mất, vì engine của ta chưa có ma sát: một quả bóng trượt trên mặt đất sẽ trượt mãi tới khi rơi khỏi mép. 4. Cách thứ hai: lò xo

Cách thứ hai là tưởng tượng giữa 2 vật đang lún vào nhau có một cái lò xo bị nén. Lò xo bị nén càng sâu thì đẩy càng mạnh, theo định luật Hooke: lực bằng độ cứng k nhân độ nén. Cách này có tên là penalty method (độ lún bị "phạt" bằng một lực đẩy). Lực thì tạo ra gia tốc, gia tốc nhân dt ra lượng vận tốc thay đổi, y như trọng lực ở blog trước: 
class PhysicsWorld {
	constructor(gravity = new Vector3(0, -9.81, 0)) {
		...
		this.stiffness = 2000;		// <---------------------
	}
	...
	resolveContact(colliderA, colliderB, contact, dt) {
		let rigidbodyA = colliderA.rigidbody;
		let rigidbodyB = colliderB.rigidbody;
		let velocityChange = Vector3.mul(contact.normal, this.stiffness * contact.depth * dt);
		if (rigidbodyA != null) rigidbodyA.velocity = Vector3.sub(rigidbodyA.velocity, velocityChange);
		if (rigidbodyB != null) rigidbodyB.velocity = Vector3.add(rigidbodyB.velocity, velocityChange);
	}
}
Engine chưa có khối lượng, nên mình coi như mọi vật nặng 1 kg, khi đó gia tốc bằng đúng lực (\(a = F/m\)). Khác với cách đẩy ra (chia đôi độ lún cho 2 vật), ở đây mỗi vật nhận nguyên velocityChange, ngược chiều nhau: lò xo đẩy 2 đầu với cùng một lực (lực và phản lực), 2 vật cùng nặng 1 kg thì vận tốc đổi cùng một lượng. Phần đẩy vị trí của cách đầu tiên bị bỏ hẳn. step truyền thêm dt vào resolveContact. Mình thêm một slider Stiffness (từ 50 tới 20000) để chỉnh k:

Kết quả, bạn thử 3 giá trị: để nguyên 2000, kéo xuống khoảng 100 rồi bấm Reset, kéo lên 20000 rồi bấm Reset:
  • 2000: bóng nảy loạn xạ không dừng, có quả nảy lên cao gần bằng độ cao lúc thả (khoảng 8), văng qua tường rồi trượt ra khỏi mép mặt đất. Lò xo này không có gì làm chậm nó lại, bị nén bao nhiêu thì bung ra bấy nhiêu.
  • 100: lò xo quá mềm, bóng lún sâu vào mặt đất. Rơi từ trên cao xuống thì lún quá nửa quả, tâm lọt vào trong hộp, và rơi xuyên qua luôn.
  • 20000: bóng nổ tung bay khắp nơi.
Tại sao lò xo cứng lại nổ? Lấy một quả bóng rơi xuống đất với vận tốc 9 m/s. Va chạm chỉ được phát hiện ở bước đầu tiên mà nó đã lún vào, và trong 1 bước 1/60 giây nó đi được 9/60 = 0.15 mét, nên lúc được phát hiện nó có thể đã lún tới 0.15. Lò xo thật thì bắt đầu đẩy từ lúc lún 0.001, đẩy nhẹ rồi mạnh dần, liên tục, nên quả bóng bị hãm lại từ từ và với lò xo đủ cứng thì không bao giờ lún được tới 0.15. Còn ở đây, ngay bước đầu tiên nó nhận một lượng vận tốc bằng k nhân 0.15 nhân 1/60:
  • k = 2000: 5 m/s mỗi bước, phải 2 bước mới hãm hết 9 m/s rồi đẩy ra dần.
  • k = 20000: 50 m/s ngay trong một bước, quả bóng đang lao xuống 9 m/s bật ra với 41 m/s, nhanh gấp 4 lần lúc lao vào.
Lò xo càng cứng thì cú đẩy của bước đầu tiên đó càng quá tay. Chia nhỏ dt thì độ lún lúc được phát hiện nhỏ hơn và lực được đo lại thường xuyên hơn, nên lò xo cứng mới chạy được, nhưng phải tính rất nhiều bước. Ngoài ra phải thêm một lực cản (damping, lực ngược chiều vận tốc) mới không nảy mãi, lại thêm một thông số cần chỉnh. Vì vậy với vật rắn penalty method ít được dùng.

5. Cách thứ ba: impulse

Nhìn lại code lò xo: mỗi bước nó đổi vận tốc của 2 vật một lượng, và lượng đó do một cái lò xo mình tự bịa ra quyết định, nên có lúc quá ít (lún), có lúc quá nhiều (nổ). Cách thứ ba cũng đổi vận tốc của 2 vật một lượng mỗi bước, nhưng không bịa nữa: nó tính ra đúng lượng cần đổi để ngay sau bước đó 2 vật tách nhau ra theo kiểu ta muốn.

Đầu tiên là 2 vật nhận bao nhiêu so với nhau. Nếu 2 vật nặng bằng nhau thì đổi vận tốc bằng nhau, ngược chiều, như lò xo. Nhưng một quả bóng bàn đâm vào quả bowling thì quả bóng bàn bật ra còn quả bowling gần như không nhúc nhích. Vật lý cấp 3 cho ta quy tắc:
  • Động lượng (momentum) của một vật là khối lượng nhân vận tốc, \(\vec{p} = m\vec{v}\).
  • Khi 2 vật va chạm với nhau, tổng động lượng của 2 vật không đổi (bảo toàn động lượng): vật này mất bao nhiêu động lượng thì vật kia nhận bấy nhiêu.
  • Lượng động lượng một vật nhận được gọi là xung lượng (impulse), ký hiệu \(\vec{J}\). Nhận \(\vec{J}\) thì vận tốc thay đổi \(\Delta\vec{v} = \vec{J}/m\): cùng một impulse, vật nặng gấp 100 lần thì vận tốc đổi ít hơn 100 lần.
(Liên hệ với lực: một lực \(\vec{F}\) không đổi trong thời gian \(\Delta t\) tạo gia tốc \(\vec{a} = \vec{F}/m\), vận tốc đổi \(\Delta\vec{v} = \vec{a}\,\Delta t = \vec{F}\Delta t / m\), tức là xung lượng của nó là \(\vec{J} = \vec{F}\Delta t\). Cái velocityChange của lò xo cũng chính là một xung lượng. Lúc va chạm, lực giữa 2 vật rất lớn mà thời gian rất ngắn, ta không cần biết từng cái, chỉ cần biết tích của chúng.)

Vậy để phản hồi va chạm, ta chỉ cần tính một con số: độ lớn của impulse \(J\) theo hướng pháp tuyến \(\vec{n}\). B nhận \(J\vec{n}\), A nhận \(-J\vec{n}\) (bảo toàn động lượng), mỗi vật chia cho khối lượng của mình để ra vận tốc thay đổi. Chỉ theo hướng pháp tuyến vì 2 bề mặt chỉ đẩy nhau ra, còn phần vận tốc trượt dọc theo mặt chạm thì phải có ma sát mới cản lại, blog 7 mới làm. Để tính \(J\), ta cần biết sau va chạm 2 vật phải tách nhau ra như thế nào.

Gọi \(v_n\) là vận tốc tương đối của B so với A theo hướng pháp tuyến: $$v_n = (\vec{v}_B - \vec{v}_A) \cdot \vec{n}$$ \(v_n < 0\) nghĩa là B đang lao vào A (đi ngược hướng pháp tuyến), \(v_n > 0\) là đang tách ra. Ngoài đời, sau va chạm 2 vật tách ra với vận tốc bằng một phần vận tốc lúc lao vào, tỉ lệ đó gọi là hệ số đàn hồi (coefficient of restitution) \(e\): \(e = 0\) là không nảy chút nào (cục đất sét), \(e = 1\) là nảy lại hoàn toàn (bóng siêu đàn hồi). Vậy ta muốn sau va chạm: $$v_n' = -e \cdot v_n$$ (dấu phẩy trên \(v_n'\) nghĩa là giá trị sau va chạm.) Sau khi nhận impulse, vận tốc của 2 vật là: $$\vec{v}_A' = \vec{v}_A - \frac{J\vec{n}}{m_A} \qquad \vec{v}_B' = \vec{v}_B + \frac{J\vec{n}}{m_B}$$ Thay vào công thức của \(v_n'\): trong ngoặc là \(\vec{v}_B + \frac{J\vec{n}}{m_B} - \vec{v}_A + \frac{J\vec{n}}{m_A}\) (trừ một số âm thành cộng), tách phần có \(J\) ra, và nhớ \(\vec{n} \cdot \vec{n} = 1\) vì \(\vec{n}\) là vector đơn vị: $$v_n' = (\vec{v}_B' - \vec{v}_A') \cdot \vec{n} = (\vec{v}_B - \vec{v}_A) \cdot \vec{n} + J\left(\frac{1}{m_A} + \frac{1}{m_B}\right) = v_n + J\left(\frac{1}{m_A} + \frac{1}{m_B}\right)$$ Cho nó bằng \(-e \cdot v_n\) rồi chuyển vế: $$J = \frac{-(1 + e)\, v_n}{\frac{1}{m_A} + \frac{1}{m_B}}$$ Một vật tĩnh như mặt đất thì coi như nặng vô hạn, \(\frac{1}{m} = 0\), nó không nhận được tí vận tốc nào từ impulse. Vì công thức chỉ dùng \(\frac{1}{m}\) chứ không dùng \(m\), mình lưu luôn nghịch đảo khối lượng (inverseMass) trong Rigidbody, vật không có Rigidbody thì inverseMass là 0:

Khi 2 bề mặt khác nhau chạm nhau, mình lấy cái lớn hơn (Box2D, physics engine 2D mà mình nhắc ở blog trước, cũng làm vậy), để một quả bóng nảy vẫn nảy được trên mặt đất không nảy. Hàm resolveContact chính là công thức ở trên: 
getInverseMass(rigidbody) {
	return rigidbody != null ? rigidbody.inverseMass : 0;
}

getVelocity(rigidbody) {
	return rigidbody != null ? rigidbody.velocity : new Vector3(0, 0, 0);
}

resolveContact(colliderA, colliderB, contact) {
	let rigidbodyA = colliderA.rigidbody;
	let rigidbodyB = colliderB.rigidbody;
	let inverseMassA = this.getInverseMass(rigidbodyA);
	let inverseMassB = this.getInverseMass(rigidbodyB);

	let relativeVelocity = Vector3.sub(this.getVelocity(rigidbodyB), this.getVelocity(rigidbodyA));
	let normalVelocity = Vector3.dot(relativeVelocity, contact.normal);
	if (normalVelocity > 0) return;

	let restitution = Math.max(colliderA.restitution, colliderB.restitution);
	let impulseMagnitude = -(1 + restitution) * normalVelocity / (inverseMassA + inverseMassB);
	let impulse = Vector3.mul(contact.normal, impulseMagnitude);
	if (rigidbodyA != null) rigidbodyA.velocity = Vector3.sub(rigidbodyA.velocity, Vector3.mul(impulse, inverseMassA));
	if (rigidbodyB != null) rigidbodyB.velocity = Vector3.add(rigidbodyB.velocity, Vector3.mul(impulse, inverseMassB));
}
Dòng if (normalVelocity > 0) return;: nếu 2 vật đã đang tách ra thì không làm gì cả. Không có dòng này thì 2 vật vừa nảy ra xong mà vẫn còn lún một chút ở bước sau sẽ bị kéo ngược vào lại (impulse ra số âm). Vật tĩnh thì getVelocity trả về vector 0. step không cần truyền dt nữa, impulse không phụ thuộc thời gian.

Lý do: impulse chỉ sửa vận tốc, không sửa vị trí. Va chạm chỉ được phát hiện sau khi quả bóng đã lún vào, mà trong 1 bước 1/60 giây một quả bóng chạm đất với vài m/s tới hơn chục m/s (tùy nó được thả cao cỡ nào, và có bị quả khác đè xuống không) đi được từ vài phần trăm mét tới khoảng 0.2 mét. Impulse làm nó ngừng đi xuống, nhưng độ lún đã có thì vẫn còn nguyên. Với restitution lớn thì quả bóng nảy lên nên độ lún tự hết, còn với restitution 0 thì không gì kéo nó lên lại.

6. Sửa độ lún

Cách sửa đơn giản nhất: sau khi xử lý vận tốc, đẩy 2 vật ra một ít theo pháp tuyến. Không đẩy hết độ lún trong 1 bước như cách đầu tiên, mà chỉ đẩy một phần, cụ thể 20% (correctionPercent), và chừa lại 0.01 (allowedPenetration) không đẩy: 
class PhysicsWorld {
	constructor(gravity = new Vector3(0, -9.81, 0)) {
		...
		this.allowedPenetration = 0.01;		// <---------------------
		this.correctionPercent = 0.2;		// <---------------------
	}
	...
	step(scene, dt) {
		...
			this.resolveContact(colliders[i], colliders[j], contact);
			this.correctPositions(colliders[i], colliders[j], contact);		// <---------------------
		...
	}
	...
	correctPositions(colliderA, colliderB, contact) {
		let rigidbodyA = colliderA.rigidbody;
		let rigidbodyB = colliderB.rigidbody;
		let inverseMassA = this.getInverseMass(rigidbodyA);
		let inverseMassB = this.getInverseMass(rigidbodyB);

		let correctionDepth = Math.max(contact.depth - this.allowedPenetration, 0) * this.correctionPercent;
		let correction = Vector3.mul(contact.normal, correctionDepth / (inverseMassA + inverseMassB));
		if (rigidbodyA != null) rigidbodyA.transform.position = Vector3.sub(rigidbodyA.transform.position, Vector3.mul(correction, inverseMassA));
		if (rigidbodyB != null) rigidbodyB.transform.position = Vector3.add(rigidbodyB.transform.position, Vector3.mul(correction, inverseMassB));
	}
}
  • Chỉ đẩy 20% phần lún mỗi bước: từ 0.2 xuống gần 0.01 mất khoảng 20 bước, tức khoảng 1/3 giây, bạn sẽ thấy quả bóng trồi lên từ từ chứ không giật lên trong 1 frame. Con số 20% mình lấy theo bài viết của Randy Gaul (link ở dưới), bài đó gợi ý khoảng 20% tới 80%.
  • Chừa lại 0.01: khi độ lún còn dưới 0.01 thì thôi không đẩy nữa, quả bóng nằm yên với độ lún khoảng 0.01, nên boxVsSphere và sphereVsSphere luôn phát hiện nó đang chạm ở mọi bước (2 hàm này so sánh >=, vừa khít là coi như không chạm). Ở blog này nhìn bằng mắt thì không thấy khác, nhưng các blog sau sẽ cần chuyện một vật nằm yên luôn có va chạm.
  • Chia cho tổng nghịch đảo khối lượng rồi nhân với nghịch đảo khối lượng của từng vật: vật nhẹ bị đẩy nhiều hơn vật nặng. Hai vật nặng bằng nhau thì mỗi vật bị đẩy một nửa, cộng lại đúng bằng correctionDepth.
Cách sửa này mình lấy từ bài viết của Randy Gaul (gọi là linear projection). Kết quả:
Lúc các quả bóng mới rơi xuống thì dòng Max penetration vẫn nhảy lên cao, nhưng khi chúng đã nằm yên thì nó là khoảng 0.010, đúng bằng phần chừa lại, các quả bóng nằm đúng trên mặt đất (nhìn những quả nằm sát đáy).
